Reference answers and options are advisory, not ground truth. Matching them does not make unsupported reasoning correct.

# 2. Two-pass role decision

Judge each step internally in two passes. Do not output separate pass fields.

## Pass A: contextual PRM correctness

- `C`: the complete step is substantively correct in its actual reasoning context.
- `I`: it contains an intrinsic substantive error, or an unresolved upstream error materially invalidates it.
- `U`: evidence is insufficient to judge the complete step reliably.

A locally valid calculation from an erroneous input is contextually `I`. A step after an error is `C` only when unaffected by that error or when it validly corrects/bypasses it. If a fixed step contains both a valid correction and a new substantive error, it is `I`. Never assign `C` merely because a step states the reference answer or a matching option.

## Pass B: role

- `correct` (`C`): correct and does not terminate an earlier error.
- `cessation` (`C`): validly terminates earlier error(s) through justified correction or a valid replacement route.
- `new_error` (`I`): introduces a substantive intrinsic error; it may also inherit an earlier error.
- `propagated_error` (`I`): adds no new substantive error but materially continues earlier error(s).
- `unverifiable` (`U`): cannot be judged reliably.

Thus `correct/cessation -> C`, `new_error/propagated_error -> I`, and `unverifiable -> U`.

# 3. Cessation: operational rule

Use `cessation` if and only if:

1. at least one earlier step is erroneous;
2. the complete current step is contextually correct; and
3. it terminates the earlier error by either:
   - **correction**: identifies, refutes, recomputes, or replaces an erroneous formula, assumption, value, derivation, or conclusion with a justified correct one; or
   - **bypass**: establishes a valid alternative route from correct evidence, no longer uses the erroneous result, and functionally replaces that path for later reasoning or final-answer support.

Correction may be explicit or implicit. Phrases such as "the previous step was wrong" are not required when functional replacement is clear.

For one recovery event, mark the earliest step where the error is corrected or a valid replacement route is clearly established. Later correct continuation is normally `correct`, not repeated cessation.

In `caused_by`, list the minimal earlier erroneous steps directly corrected, invalidated, or bypassed. Cessation is a corrective relation, not necessarily an inferential dependency; a valid independent route may have no input reference to the erroneous output and may produce a causal edge with `via: []`.

Do NOT use `cessation` for:

- an unrelated correct step after an error (`correct`);
- a locally valid continuation using erroneous input (`propagated_error`);
- a failed correction that introduces an error (`new_error`);
- stating a different value without valid derivation;
- copying/appealing to a reference answer, provided solution, answer key, or option;
- claiming a value "matches option X" when the derivation does not support it;
- a correct statement that does not correct or replace the erroneous path;
- use of an unaffected, still-correct output from an erroneous step, unless the actual error is corrected/replaced.

# 4. Error types and role fields

Use only these coarse `error_type` values:

- `problem_understanding`
- `method_or_formula`
- `derivation_or_logic`
- `calculation`
- `unit`
- `assumption_or_condition`
- `missing_evidence`
- `answer_mismatch`
- `other`

Field rules:

- `correct`: `error_type=null`, `caused_by=[]`, `note=null`.
- `cessation`: `error_type=null`; nonempty `caused_by`; concise note naming the justified correction/replacement.
- `new_error`: intrinsic `error_type`; concise note; `caused_by` may be empty or nonempty.
- `propagated_error`: `error_type=null`; nonempty directly responsible `caused_by`; concise note.
- `unverifiable`: `error_type="missing_evidence"`, `caused_by=[]`, concise note.

A purported correction that only copies a reference/option is `new_error`, normally `derivation_or_logic` or `answer_mismatch`, not cessation.

# 5. Error causality

`caused_by` is direct error causality for erroneous roles and corrective causality for cessation, not chronological adjacency.

- Sources may be non-adjacent earlier steps.
- A later step may be correct if unaffected by an earlier error.
- `new_error` with empty causes is independent; with nonempty causes it is mixed (inherits an error and adds a new one).
- `propagated_error` must descend from an originating `new_error`.
- For `new_error/propagated_error`, list only errors whose erroneous content materially causes current invalidity.
- For `cessation`, list only errors whose effect is validly terminated.

`first_error` is exactly the earliest `new_error`, or `null` if none exists.

# 6. Audit material dependencies

Teacher A provides provisional `in` lists. Return only edits materially affecting correctness, propagation, cessation, first error, or final-answer support. Do not add rhetorical, topical, temporal, or adjacency edges.

Valid references: `q01`, earlier outputs such as `s02.o01`, and earlier assumptions such as `s02.a01`.

Valid dependency types: `data`, `formula`, `result`, `condition`.

Each edit is:

```json
["consumer_step_id", "reference_id", "dependency_type"]
```

Rules:

1. Add only content actually used; remove only materially incorrect edges.
2. Never reference undefined, current-step, or future content.
3. To change type, remove the old triple and add the new one.
4. After edits, each cause of `new_error/propagated_error` must be a direct upstream step through at least one input reference; add a missing material edge.
5. This direct-parent requirement does not apply to `cessation` because a valid replacement route may bypass the error.
6. An edge from an erroneous step does not automatically imply propagation: determine whether the specific referenced output is affected.

# 7. Contrastive examples

## A. Explicit correction

```text
s03: Computes 2.26e-27 instead of 2.26e-26.                 -> new_error
s04: Uses s03 and obtains a ten-times-too-small result.      -> propagated_error
s05: Identifies the exponent error, recomputes 2.26e-26,
     and derives the corrected result.                       -> cessation
```

For `s05`, use causes such as `["s03","s04"]` only if it directly corrects/replaces both conclusions.

## B. Implicit valid alternative

```text
s03: Applies an invalid energy formula.                      -> new_error
s04: States an unrelated correct definition.                -> correct
s06: Derives the target from momentum conservation and
     replaces the failed energy route.                       -> cessation
s07: Correctly continues from s06.                           -> correct
```

`s06` need not explicitly call `s03` wrong or consume its output.

## C. Propagation

```text
s03: Incorrectly obtains x=5.                                -> new_error
s04: Correctly multiplies that erroneous x by 2.             -> propagated_error
```

## D. Unsupported answer replacement

```text
s05: Derivation gives 2.50e28.                               -> new/propagated error
s06: "The provided solution states 2.50e29, matching D."    -> new_error
```

`s06` is not cessation because it supplies neither a valid correction nor an independent derivation.

# 8. Quality and evaluation status

Quality flags are warnings, not automatic rejection:

- `missing_external_content`: judge independently verifiable steps; use `unverifiable` only where missing evidence is necessary.
- `insufficient_segmentation`: do not split; use `unverifiable` if the fixed mixed step cannot be judged and normally set status `limited`.
- `non_reasoning`: do not invent reasoning; use `not_evaluable`, though independently checkable final claims may still be judged.

Use:

- `complete`: all fixed steps and proposed answers are adequately evaluable;
- `limited`: useful partial evaluation exists but some evidence/segmentation is insufficient;
- `not_evaluable`: no evaluable reasoning process.

If the problem itself is ambiguous or lacks necessary conditions, do not force reference agreement. Use `U` for affected judgments/answers and `limited` when appropriate.
